# index.html Agent Details

## File Overview
`index.html` is the Optimux single-page frontend: the page and its Vue 3 templates. Since Feature 23 nothing is inline or from a CDN (the Content Security Policy allows only `script-src 'self' 'unsafe-eval'` and `style-src 'self'`):
- `web/app.js`: the Vue app (formerly the inline `<script>`); `web/boot.js`: the fetch wrapper and `optimuxSafeHtml`; `web/optimux.css`: the custom styles (formerly `<style>`).
- `web/vendor/`: pinned copies of Vue 3.5.13 (global prod build; it compiles the in-page templates, hence `'unsafe-eval'`), marked 15.0.12, DOMPurify 3.2.6, highlight.js 11.9.0 (`github-dark`) and qrcode-generator 1.4.4. Version numbers are in the file names.
- `web/app.css`: Tailwind 3.4.17 + typography, built from the classes in `index.html`, `web/app.js` and the sign-in page by `scripts/build-css.sh`. **Rebuild after adding classes**; `tests/test_auth.py` fails when a class in the HTML is missing from the CSS.
- `web/logo.svg` (Feature 27): the Optimux logo, "two lanes" (one request splitting into a light lane to a small model and a heavy lane to a big one), blue `#3b82f6`. It is the favicon (`<link rel="icon">` here and on the sign-in page; `/favicon.ico` serves it too), sits before the name in the header and the Dashboard sidebar, and above the name on the sign-in page. `docs/images/logo.svg` is the same file for the README.
- No `style="…"` attributes (blocked by the CSP); use Tailwind arbitrary classes such as `[animation-delay:0.1s]`. `:style` bindings are fine (Vue sets them through the CSSOM).

## Core Functionality
- **Sizes:** the dashboard uses one step larger text than the chat (13 px for small text, 15 px for body text); its content is `max-w-6xl` (`max-w-7xl` for the Guide, whose contents column is `w-80` and article `max-w-5xl`).
- **Guide (Feature 20):** Dashboard → Guide (group Help; also the "?" button in the header, and mentioned in the greeting). `loadGuide` fetches `/api/guide` once; `parseGuide` collects the `##`/`###` headings outside code fences (`toc`, slugged ids, unique), splits the text into searchable chunks, renders with marked and gives the rendered h2/h3 the same ids (`g-<slug>`) in order. The sticky left column shows the contents (active entry follows scrolling via `onDashScroll` on `#dash-scroll`); typing in its search box replaces the contents with results (all words must match; title matches first; snippets escaped and highlighted). `goGuide(id)` scrolls to a heading. On narrow screens the search and results sit above the text. Inline code in `.prose` (chat and guide) has no literal backticks.
- **Help tips:** explanations live behind a small "?" (`<help-tip text="...">` or `<help-tip wide>` with HTML in the slot), a component registered on the app (`HelpTip`). Hover shows the box; a click pins it until an outside click; scrolling closes it. The box is `position: fixed` next to the button (above it near the bottom of the window), so scroll containers never clip it. A "?" inside a label doesn't toggle the label's checkbox. Section hints from `dashboardSections` appear as a "?" next to each dashboard title. Keep slot content free of `<p>`/`<ul>` when the tip sits inside a `<p>` (the HTML parser would close the outer paragraph).
- **Auth (Feature 23):** the browser is signed in by an HttpOnly session cookie set on `/login` (`web/login.html` + `web/login.js`, plain JS); no secret is stored where scripts can read it. `web/boot.js` wraps `window.fetch`: a 401 from `/api/` sends the browser to `/login?next=<path+hash>` (`optimuxToLogin`); a 400 alerts the server's `detail` and throws, so callers skip their "Saved" message. **Dashboard → System** has the security checklist (`/api/security`) and the Sign-in card (`authInfo`, `fetchAuth`, `signOut`, `signOutOthers`, `changePassword`, `totpStart`/`totpConfirm`/`totpDisable`; the QR code is a data URL from qrcode-generator), plus the token for scripts (`rotateToken`). An `auth_event` WebSocket message (`signin`/`signout`, sent by the server to every signed-in socket) refreshes that list when System is open; `signin` also shows `signinNotice` (browser via `browserLabel(ua)`, address, time) until dismissed, with "Not me: sign out the others".
- **Sanitizing:** everything rendered with `v-html` goes through `optimuxSafeHtml` (DOMPurify; no `style`, forms or buttons): `renderMarkdown` sanitizes the marked output **before** adding the View buttons, and the guide, guide snippets and the cost chart SVG are sanitized too.
- **Server mode:** `sandboxInfo.server_mode` (from `/api/sandbox`, fetched on mount) disables Auto-approve and hides "Always Approve". Execution also has the "Command environment and limits" card (`commandEnvText`, `saveCommandSettings`, `limit_*` settings).
- **WebSocket:** `connect()` opens `/ws` (`wss://` over HTTPS); the session cookie signs it in and the server answers `auth_ok` right away. `wsState` (connecting, connected or disconnected) drives the status dot next to the logo. If the connection drops, it reconnects with backoff (1 s doubling to 15 s), and `auth_ok` then reopens the project's latest chat. A close with 4401 (signed out, or signed out elsewhere) goes to the sign-in page instead of retrying.
- **Thinking:** `thinking` messages extend a `thinking` block (or start one). It renders collapsed as "Thinking… / Thinking (n chars)" with a ▸ toggle and its own Copy (`copyThinking`). Exports include it as a `<details>` section. When a reply's executor calls report thinking tokens (`usage.replyReasoning`, which excludes the Conductor's call) but no thinking text arrived (Gemini returns only summaries, often none for short thinking), `done` adds a placeholder: "Thinking: N tokens (the model didn't share the text)". The reply chip and the Usage tables show thinking tokens. Each non-local model card has a Thinking selector (Default, Minimal, Low, Medium, High; `POST /api/models/thinking`) with a support hint from `supports_thinking`.
- **Errors:** an `error` reuses the request's empty reply box when nothing has arrived yet (e.g. a refused `/name`), so no blank box is left above it; otherwise it gets its own box.
- **Reply layout:** A reply has `blocks` (`text`, `cmd`, `note`, `thinking`) rendered in the order they happened. Tokens extend the last text block or start a new one after a command, so text from separate steps isn't glued together. `cmd` blocks are the same objects as in `commands`, so `command_output` updates both. Replies without blocks (the greeting, errors) use the older `commands` + `content` layout.
- **Chat layout:** the app is `max-w-6xl`. `#chat-container` has right padding and a stable, thin scrollbar gutter (`scrollbar-gutter: stable`), so the scrollbar never touches the user's prompts; the input area has matching padding.
- **Command cards:** the header puts the command (`flex-1 min-w-0`) and the exit badge (`flex-shrink-0 whitespace-nowrap`, a small green or red pill) side by side, so long commands wrap without squeezing "exit N". A **View** button under each card opens the code viewer.
- **Code viewer:** a side panel (`viewer`, right 58%, max 1000px, full width on small screens) with syntax highlighting, line numbers, a Language selector (`viewerLanguages`, incl. Auto-detect and Plain text), Wrap, and Copy per section. Esc closes it first (before leaving the dashboard or stopping a request).
  - `openCmdViewer(cmd)` shows two sections: Command (always Bash) and Output. `guessOutputLang` picks the output language from the command (the last `cat`/`head`/`tail`/`nl`/`sed -n` part of a chained command and the file extension; `git diff`/`git show` → Diff; valid JSON → JSON; otherwise Plain text). The subtitle shows the exit code (or "still running (snapshot)") and the project.
  - Fenced code blocks in replies get a View button in their corner: `renderMarkdown` wraps each `<pre>` in `.cm-pre` with a `data-cm-view` button, and `onChatClick` (a delegated click handler on `#chat-container`) opens the block with its `language-*` class (aliases such as `sh`, `py`, `vue` mapped by `LANG_ALIAS`).
  - `highlightLines` highlights once when the panel opens or the language changes (not on every render), then splits the HTML into numbered lines, closing and reopening spans that cross a newline. Plain text above 400 KB, or auto-detect above 100 KB, is shown unhighlighted.
- **Agent messages:** Each reply has an `events` list (`{text, kind}`, where `kind` is `route`, `switch` or `info`), shown in order at the top instead of a single overwritten note.
  - A `system` message with `tier`/`model` (the "Routed to" message) sets `msg.tier` and `msg.model`.
  - When an "Escalated to" or "Fell back" event arrives after output has started, a `note` block marks the switch where it happened.
  - `budget` messages add a note block; when the state is `blocked` or `paused`, the reply gets a **Raise budget** button that opens Settings → Usage.
  - **Interruptions:** `msg.interrupted` records why a reply ended early: `stopped` (from the `stopped` message), `step_limit`, `paused` or `blocked` (budget), `error`, or `aborted` (the model repeated itself). The last reply then shows a label (`interruptionLabel`) and actions:
    - **Continue ↻** (for stopped, step limit, paused and aborted) sends "Continue from where you stopped.".
    - **Retry ⟳** (`retryFrom`) resends the original request; `lastPromptBefore` skips earlier "Continue" prompts.
    - **Raise budget** appears for budget stops.
  - `usage` messages add up into `msg.usage` (`calls`, `tokens`, `cost`, `costKnown`, `ms`, `estimated`), shown as a chip under the reply: calls per model (`callsLabel`, e.g. "Gemini 8 + Claude Sonnet 5.5 1 calls" when a reply escalated), tokens, cost (with `+` or `cost ?` when a price is unknown) and time. They also update `sessionUsage` for the header chip.
- **Chat controls:**
  - **New chat** (next to the model selector) sends `{"type":"new_chat"}`; on `chat_reset` the message list is replaced with a "New chat started" note.
  - **Escalate ↑** appears under the last reply when it ran on the simple tier and a Complex Executor is configured. It sends `{"type":"escalate"}` into a new reply.
  - Typed commands `/new`, `/simple` and `/complex` also work.
- **Stop:** While a request is running or an approval is pending, the Send button becomes a red Stop button; Esc does the same. `stopGeneration()` sends `{"type":"stop"}` and hides any approval widget. `done` re-enables the input; if no `done` arrives within 5s, the input is released anyway.
- **Approval:** the box shows a "🔒 sandboxed" or "not sandboxed" badge (`pendingSandboxed`), and the outside-the-project text depends on it. `approval_request` shows the Approve/Reject widget and locks the input. Requests with `always_ask` (project actions, `pendingAction`) are never auto-approved, say so, and hide Always Approve.
- **New project form (Feature 25):** the `project-form` component (`ProjectForm` in web/app.js: name with live checks against `projectsList` and the end of the path, Basic/Python cards, Git and GitHub switches, Private/Public cards, description with a 350 counter, "Open it when it's ready", error box, Create/Cancel; GitHub is disabled with the reason and a *Set up GitHub* link until `github.ready`). Used twice:
  - **In the chat** (`compact`, two columns): an `approval_request` with `form` sets `pendingForm` and shows the form instead of the yellow box; Create sends `approval_response` with `form` (`sendProjectForm`), Cancel rejects. It uses `githubInfo` once that is ready (after setting GitHub up in the Dashboard), else the request's `github`.
  - **The dialog** (`newProject`, opened by the header **+** or the Projects tab's "+ New project" card): `POST /api/projects`; 422 errors appear in the form; on success a toast, the project list refresh and, with `switch`, `switchProject`.
- **Archive, restore, delete (fix25a):** Projects cards get **Archive** (`archiveFromDashboard`, via `askConfirm`; disabled for the active project while a request runs) and *archived*/*deleted* marks; the **Archived projects** list (`archivedProjects`) has Restore and Delete permanently…, which opens `deleteBox`: keep or delete the records, the GitHub note and settings link, and a field (focused, paste blocked) that must read the phrase (`deletePhraseOk`, the server's rule). `deletedProjects` ({name: ts}, refreshed with the overview and usage) drives the `deleted-tag` component (red "deleted" with the date in its tooltip) and struck-through names in Usage (By project, Memory updates), Budgets (read-only row: "no budget: the project is deleted"), the History page and drawer. Esc closes the delete and New project dialogs (only through the page-wide handler: the overlays have no Esc handler of their own, which used to close the dialog and the Dashboard together). The GitHub box appears only for a project with a GitHub remote (`item.github_settings`; fix25d); then the dialog asks `/api/projects/archived/{folder}/github` and shows: checking…, still exists (with the settings link), doesn't exist any more (no link), deleted or private (without sign-in; link to check), or couldn't check (reason). A `project_archived` message (any page) refreshes the lists and leaves the project if it is open (`leaveArchived`). A delete error after the dialog was closed becomes a toast; paste and drop are blocked in the phrase field.
- **Role help (fix26a):** `ROLE_HELP` (web/app.js) describes each Usage role (conductor, simple, complex, override, curator, skill_draft, test); By role names with an entry get a dotted underline and the description as their tooltip. The skills count's tooltip names both skill locations: global (`global_dir`) and project (`project_dir`, or `<Workspace>/<project>/<project_dir_name>` when no project is active).
- **Groups (fix25e):** `usageRows(groupKey)` returns a Usage table's rows: live ones (archived ones tagged), then for By project and Memory updates one `summary` row "Deleted projects (N)" with their summed numbers, then those rows (`gone`) when `openGroups['usage-…']` is set. `budgetRows` is `{live, archived, deleted, deletedSpent}`: live rows are editable; archived ones (budget `paused`, from `/api/budgets`) and deleted ones sit under closed group rows. `activeBudgets` leaves paused budgets out of the Overview. The Projects grid hides cards whose folder is archived or deleted; deleted ones are in a closed "Deleted projects (N)" list (Chats, Memory); archived rows got a Chats button. `openGroups` / `toggleGroup` keep the open state in localStorage (`optimux.openGroups`, try/catch).
- **Paths (fix25b):** `workspacePath`, `archivePath` and `projectPath(name)` (from `appSettings.projects_root`) show where things are: a Workspace folder bar at the top of Projects (copy, Change in Scope), the `.archive` path above Archived projects and each folder under its name, the archive/restore toasts (`archived_to`, `path`), the header project menu's tooltip, and a `projects` row in System → Files. `copyPath` uses `writeClipboard`.
- **From GitHub (Feature 26):** the New project dialog has tabs (`newProject.tab`: `new` | `github`; `openNewProject('github')` from the Projects page's "Clone from GitHub"). `ghImport` holds the list (`loadGithubRepos`, ↻ reloads), search (`filteredRepos`, first 300), the picked repo, the folder name (`importNameProblem`), "Open it when it's ready" and the `job`. `startClone` posts (`posting` blocks a second click), `pollClone` polls every 0.7 s until done (toast, list refresh, close the dialog if it's still that job, switch), failed (toast with git's last lines) or cancelled; a non-OK poll (server restarted, signed out) ends the job as failed instead of spinning forever. The list reloads each time the tab opens; at most 300 matches are shown (the count says so). Jobs are matched by `id` (Vue stores a proxy). The clone continues if the dialog closes. `projects_changed` (also from the server's Workspace watcher) refreshes the project list and, when open, the Projects page.
- **Toasts (Feature 25):** `toasts` / `pushToast({kind: success|warn|info, title, text, link, linkLabel, timeout})`, top right, sliding in (`cm-toast` transition in web/optimux.css), gone after 6 s (12 s for warnings). `project_created` (live only) shows one.
- **Moving the chat after a switch (Feature 25):** a live `project_switched` sets `moveChatTo`; on the next `done` the page sends `open_session latest` (the new project's chat) and shows a "Now in …" toast. The old chat stays in History under its project.
- **Dashboard → GitHub (Feature 25):** status (gh and its version, the sign-in source and account, Check it, Remove token), token steps with links and a password field (Check and save → `POST /api/github`; green, yellow with a warning, red on error), and Who commits (`gitIdentity`, its own form → `POST /api/github/identity`, never part of `saveSettings`). When the sandbox is off, a yellow box says commands could read secrets.env (or use gh's own sign-in). `moveChatTo` is cleared on `auth_ok` and `session_loaded`, so a reconnect doesn't move the chat twice.
- **Workspace events:** `project_switched` updates the header's active project, the project list and the costs (ignored during a replay); `projects_changed` refreshes the project list. The projects root is called **Workspace** everywhere in the UI (`projectLabel`, which also maps the backend's `(no project)` usage/budget key); the backend still stores it as an empty project name. The header dropdown's tooltip explains what the Workspace is for. The command keeps its line breaks (`whitespace-pre-wrap`, scrolling past ~24 lines), so multi-line commands such as heredocs can be read before approving; command card headers do the same. When the request has `outside_paths`, a red "Outside the project" box lists them, Always Approve is hidden, and auto-approve does not apply. Otherwise, with `auto_approve` on, it answers automatically.
- **Dashboard (replaces the Settings modal):** a full-page view over the chat; the chat stays mounted, so the WebSocket, a running request and the conversation survive a visit.
  - A sidebar lists `dashboardSections` grouped into Activity (Overview, Usage, Budgets, Projects, History) and Configuration (Routing, Models, Memory, Execution, Scope, Backups, System). The dashboard opens on Overview by default. A header shows the section title, a hint and the active project.
  - **Addresses:** each section is `#/dashboard/<id>`. `openSettings(id)` opens a section and `closeSettings()` returns to `#/`. `applyHash` handles back and forward and typed addresses (including opening the page directly on a section). A `settingsTab` watcher keeps the address in sync and loads data through `enterSection` (usage data for Usage, Budgets and System; memory for Memory).
  - **Esc** leaves the dashboard first; otherwise it stops a running request. The gear opens the dashboard on the last section (Usage by default). Raise budget opens Budgets.
  - **Section contents** (the former tabs):
  - **Routing:** Conductor (a model, or "Off: always start on Simple"), Simple Executor and Complex Executor. Only these three fields are saved.
  - **Models:** Add a model (ID, name, env key, API key, optional prices in USD per million tokens). Each card shows the model ID `problem` (red), a notice from the last key save or test, and its price status (custom prices, "known (LiteLLM)", "Local model: no per-token cost", "$0 in the price list (free, or not priced)", or a yellow "Price unknown" warning) with an inline price editor. **Test** calls `POST /api/models/test`.
  - **Execution:** command approval (auto-approve); **Sandbox** (`sandboxInfo` from `/api/sandbox`: status line with "check again", the switch via `toggleSandbox`, which reverts when the server refuses, locked on when `required`; when on: network switch and extra read-only folders `sandboxPathsText` → `saveSandboxPaths`, reloaded from the server's normalized list); steps per turn (`max_steps_simple`, `max_steps_complex`).
  - **Scope:** the Workspace folder (`projects_root`). The UI calls it the Workspace folder everywhere.
  - **Memory → Project, automatic updates (Feature 17):**
    - **Settings:** the toggle (`memory_curator`), the idle minutes, and "Update now from the latest chat" (`curateNow`, which shows the chat it read, the result or reason, and the cost).
    - **Size bar:** about 4 characters per token against the 1,500-token cap; yellow above 1,200, red above 1,500.
    - **History:** `memoryVersions` from `/api/memory/project/{name}/versions`, each with a source badge (auto for the curator, you, model, undo; with a tooltip), a summary, the cost of automatic updates, the time, a coloured diff (Changes) and Undo (`undoMemoryVersion`).
  - **Memory:** edit the personal, professional and **project** markdown (project memory has its own project selector and uses `/api/memory/project/{name}`; saving creates the file).
  - **Overview:**
    - `overviewKpis`: today, this month, cache hit rate and output (with thinking share).
    - `costChart`: a 30-day stacked SVG bar chart by model from `/api/usage/daily`, with a tooltip per day.
    - Budget bars.
    - Model status: ready, needs key, cooldown or test failed, with each model's routing role.
    - The 5 most recent chats (`fetchRecentChats`), which open in the chat.
  - **Projects:** one card per project from `/api/projects/overview`: month and all-time cost, chats, budget bar, last activity, and "folder missing" when the folder is gone. Buttons: Make active (`switchProject`), Chats, Memory, Budget.
  - **History:** a full-page table (`historyPage`, `fetchHistoryPage`, `historySorted`) with a labeled filter bar: Project, Updated (any time, today, 7 or 30 days), Status (Active or Archived), Search, and Clear filters (`historyFiltered`, `resetHistoryFilters`); the table is and sortable by title, project, updated, turns or cost. Open closes the dashboard and opens the chat (`openChatFromDashboard`). Rename, Archive and Delete refresh both this table and the drawer.
  - **Usage:** the cost-per-day chart with a project filter (`chartProject`), then `/api/usage` for today, 7 days, this month or all time (totals, by project, by role, by model, by skill while using it, and skill drafting, with average time).
  - **Budgets:** **Monthly budgets**, one row per project with this month's spending, an amount (empty means no limit), Block or Warn, and Save (`POST /api/budgets`).
  - **Skills:** cards for global and project skills (`/api/skills`), each showing scope, override state, a warning when there's no description, tier, steps and thinking, usage (calls and cost) and, separately, drafting cost. An editor (`skillEditor`) is used for New (from the template), Edit and Save (`POST /api/skills/{scope}/{name}`, with server errors shown inline); Remove moves the folder to legacy. New skill opens the same name-and-scope dialog.
  - **System:** Optimux, LiteLLM and Python versions (`/api/system`); a Files panel with the `~/.optimux` layout and a collapsible list of file moves; access token rotation (`rotateToken` asks for the current token, stores the new one in this browser and shows it once); a Storage line from `/api/storage` (database path, size, usage rows, latest backup), and models in cooldown from `/api/cooldowns`, each with a **Clear** button (and **Clear all**) that calls `/api/cooldowns/clear`. After a key is saved, the model's notice also names any cooldowns that were cleared.
- **API key inputs** are `type="password"` with `autocomplete="new-password"` and password-manager ignore attributes, so browsers don't offer to save keys as a site login.
- **Sessions:**
  - **Live chat:** messages go through `handleMessage(data, replay=false)`.
  - **On connect:** `auth_ok` asks for the latest session (`open_session` with `latest`).
  - **Logo and name (header and Dashboard sidebar):** links (`href="#/"`) with `@click.prevent="goHome"`: close the Dashboard and the History drawer, then `open_session last` (the newest chat in any project, or the Workspace). Not while a reply runs or an approval is pending. `loadSession` calls `fetchConfig()` when `session_loaded.active_project_changed` is true, so the project menu follows.
  - **Reopening:** `session_loaded` rebuilds the chat with `loadSession`, which replays the stored events: `prompt` and `escalate` create the user message and reply placeholders, everything else goes through `handleMessage(ev, true)`, and replay never touches the header chips. `finalizeReply` adds what a finished reply needs (the unshared-thinking note), live on `done` or after a replay.
  - **Title:** `session_started` and `session_loaded` set `currentSession`, shown as a title line with ✎ rename.
  - **Read-only chats (fix38):** when `session_loaded` has `read_only` (the chat's project is archived or its folder is gone), `readOnlyChat` holds `{project, reason}`: the greeting says "Viewing … read only", an amber bar above the input explains why (archived: restore it in Dashboard → Projects) with **Back to <active project>** (`leaveReadOnly` → `open_session latest`), and the textarea and `sendMessage` are blocked. `newChat` and any normal `session_loaded` clear it; the header doesn't switch project.
  - **Project selector:** disabled while a reply runs or an approval is pending (fix38), so the active project can't change under a running request or leave the chat on screen belonging to another project.
  - **Switching project** (`changeProject`) saves the setting and opens that project's latest chat.
  - **History drawer** (header button): scope This project, All projects or Archived; title search; each entry shows project, date, turns and cost, with Open, Rename, Archive or Unarchive, and Delete. Delete asks for the title to be typed, and deleting the open chat starts a new one.
- **Header:** the logo with the connection dot, the active project dropdown, and one cost button ("$x this month", or "$spent / $limit this month" with a budget, in yellow from 80% and red from 100%). The button opens Budgets or Overview; its tooltip (`headerCostTitle`) gives today, month and all-time cost, the budget, and this browser session's usage. Data comes from `/api/usage?project=<name>` and `/api/budgets` (`fetchProjectUsage`), refreshed on load, on project change and after every request. "History" opens the drawer and "Dashboard" opens the dashboard; "Connecting…" or "Offline, retrying…" shows while disconnected.
- **Chat input:** Auto-resizing textarea (Enter sends, Shift+Enter adds a newline) with a borderless model override selector (`auto` = Auto-Router) and the New chat button. The Send/Stop button is icon-only.
- **Skill modes (Feature 19):**
  - **Skills page:** a global switch titled "When skills run" (Off, Manual only, Auto allowed → `skills_mode` via `setSkillsMode`) with one line per option, and the prompt cost of what is listed ("N skills listed in every request: ≈ T tokens per model call", or "Nothing listed" in green). Each card shows `/name`, a Manual/Auto switch (`setSkillMode` → `POST /api/skills/{scope}/{name}/mode`) and a note when an auto skill isn't listed because of the global mode.
  - **Slash suggestions:** typing `/` in the chat input shows `/new`, `/simple`, `/complex` and the active project's usable skills with their mode (`slashSuggestions`, none when skills are off). Arrow keys move, Enter or Tab picks (it fills `/name ` and doesn't send). Skills load at start and whenever the active project changes.
- **Cost warnings (Budgets):** "Warn me before Update memory now / Escalate ↑", explaining that they only control the warning, not the features.
- **Save as skill:** a reply in a stored chat has a "Save as skill" button. An in-app dialog (`skillDialog`, shared with New skill) asks for a name (validated) and where it's available (all projects or this project), then requests a draft from `/api/skills/draft` and opens Dashboard → Skills with the draft in the editor (marked as a draft, nothing saved until Save).
- **Confirmations:** `askConfirm({title, detail, text, ok, danger, cost, skipLabel, onSkip})` shows an in-app dialog and resolves to true or false (Esc or a click outside cancels). Undoing a memory change, removing a skill and deleting a model use it instead of the browser's `confirm`.
- **Usage tables** include "Memory updates (automatic, per project)" (`memory_updates`).
- **Cost transparency (Feature 18):**
  - **Live cost:** while a reply runs, a pulsing "So far: calls · tokens · cost" line under it updates after every model call (commands themselves are free); the usual chip replaces it when the reply is done.
  - **Estimates:** `costEstimates` from `/api/costs/estimates` (`fetchCostEstimates`, refreshed when opening Memory, before and after paid actions). `estimateText` formats "≈ $x per … (average of your last n, model)".
  - **Confirmations:** Update memory now and Escalate ask first through `askConfirm` with a `cost` line and a "Don't ask again" checkbox (`skipLabel`/`onSkip`), which turns off `confirm_update_memory` or `confirm_escalate`; both can be turned back on in Dashboard → Budgets ("Ask before extra paid actions"). The Save as skill dialog always shows the drafting estimate and that each click is charged; the button is ignored while a draft runs.
  - **Memory switch:** shows the average cost per update and this month's updates and cost.
  - **Background memory status:** `memory_updating` shows a pulsing "Updating memory…" pill in the header (`memoryStatus`); `memory_updated` turns it into "✓ Memory updated" (plus the toast) and `memory_unchanged` into "Memory: nothing new" (reason and cost in the tooltip); it fades after 4 seconds. Ignored during a replay.

- **Copy session:** When the chat has messages and nothing is generating, a button below the last message copies the session as Markdown. The export has a header (export time, active project), `## You` / `## Optimux` sections, events as `>` quotes, commands as `bash` code blocks with output and exit code (fences grow longer when the output contains backticks), the reply text, and a usage line.
