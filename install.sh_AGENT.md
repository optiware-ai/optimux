# install.sh Agent Details

## File Overview
The one-line installer (Feature 24): `curl -fsSL .../install.sh | bash`. Pure bash 4.4+, no dependencies, interactive text interface, also the library behind the `optimux` command (`scripts/optimux` sources it with `OPTIMUX_LIB_ONLY=1`). Every statement is in a function; only the last line calls `main`, so a truncated download runs nothing.

## Structure
- **Terminal interface:** `tui_init` (questions read from `/dev/tty` on fd 3, so they work under `curl | bash`; UTF-8 symbols or ASCII; 256/8 colours or none when not a terminal or `NO_COLOR`), `banner`, `step`/`section`, `ok`/`warn`/`err`/`info`/`note`/`dim`, `card` (box, aligned by visible length), `run` (spinner; output to the private log; on failure the last 15 log lines and `die`), `confirm`, `ask`, `ask_secret` (hidden, shows dots), `choose` (arrow keys/j/k/numbers; numbered list without colours). `--yes` makes every question take its default; no terminal and no `--yes` → `die`.
- **System:** `detect_system` (OS, package manager apt-get/dnf/pacman/zypper/brew, sudo, systemd), `find_python` (3.10+ with venv+ensurepip), `check_system`, `packages_for` (names per manager), `install_missing` (asks, `sudo -v` first so spinners never wait on a password).
- **Manifest:** `/etc/optimux/install.env` (server) or `~/.config/optimux/install.env` (local, 600): MODE, APP_DIR, DATA_DIR, WORKSPACE, PORT, URL, SERVICE (systemd | systemd-user | process), RUN_USER, DOMAIN, REF, REPO, NAME. `manifest_read` parses KEY=value, never sources it.
- **NAME (Feature 27, the rename from CodeMux):** the name of the install's service, user and server folders, read with `nm()`: `optimux` for new installs, `codemux` for manifests written before the rename (they have no NAME, and are found by `find_install` at `/etc/codemux/install.env` or `~/.config/codemux/install.env`). Every server path comes from it: `/opt/<name>`, `/var/lib/<name>`, `/etc/<name>/<name>.env`, `<name>.service`, `/run/<name>/<name>.sock`, `/etc/caddy/<name>.caddyfile`; `server_unit <name>` writes `deploy/optimux.service` with those names (unchanged for `optimux`).
- **`upgrade_old_install`** runs after `find_install` (installer and command) and at the end of `cli_update`, once the new code is in the program folder (`optimux_backend/` exists; before that, nothing changes and the old version keeps working):
  - **local:** stops the service, moves `~/.local/share/codemux` to `~/.local/share/optimux` with a fresh virtual environment (the old one is kept until the new one works; on failure everything goes back), `~/.codemux` to `~/.optimux`, replaces `codemux.service` (user) with `optimux.service`, `~/.local/bin/codemux` with `optimux`, writes the new manifest and deletes the old one, starts it again if it was running. Only the default locations move; the Workspace never does.
  - **server:** keeps every name (renaming a system user and folders under a running service is risky); points the unit's `ExecStart` at `optimux_backend.main:app` and replaces `/usr/local/bin/codemux` with `optimux`.
- `safe_rm` accepts folders named `codemux` too; uninstall also removes `CodeMux installer` lines from the shell profile and Caddyfile.
- **Setup via `admin`** (`python -m optimux_backend.admin`, as the optimux user on servers): password (`set_password_interactive`), provider + key + models + routing + optional test (`configure_provider`, presets in `CM_PROVIDERS` at the top), GitHub (`configure_github`, Feature 25: `install_gh` installs `gh` from the distribution (always with sudo when not root, also for `optimux github` on a local install: a `local CM_SUDO` override), or, after a yes, GitHub's apt repository via `add_gh_repo` when apt has no candidate (never under `--yes`). `add_gh_repo` checks every step (it runs under `||`, where set -e is off), downloads the key to a temp file first and removes a half-added source and key on failure; optional, failures only warn through `CM_SOFT=1 run`; then the token on stdin to `admin set-github`, output in a temp file parsed with `json_str`; with `--yes` only gh is installed), sandbox (`configure_sandbox`, `fix_apparmor` for Ubuntu 23.10+).
- **Local** (`install_local`, 6 steps): `~/.local/share/optimux` + `.venv`, data `~/.optimux`, Workspace (default `~/git` if it exists), first free port from 8000, systemd user unit if available (else a background process with a pid file in `DATA_DIR/logs`), `~/.local/bin/optimux`, PATH hint (`path_hint`).
- **SSH tunnel (server without a domain):** `tunnel_command` builds the command to run on the user's own computer: their login (`SUDO_USER`, else the current user), the server's public address (`public_ip`, else the first `hostname -I` address, else a placeholder), `-p` when SSH listens on another port, and the service port. It is shown in the final card, by `optimux open` and by `optimux status`.
- **PATH:** when `~/.local/bin` isn't in the PATH the installer runs with, `path_hint` sets `CM_PATH_LATER` and offers to add it to `~/.bashrc` or `~/.zshrc` (never twice; not under `--yes`), even when `~/.profile` mentions it: Ubuntu's `~/.profile` adds it only at login, and only if the folder existed then, so new terminals wouldn't find `optimux` before a new login. The installer can't change the PATH of the terminal that started it, so `finish_local` puts `export PATH="$HOME/.local/bin:$PATH"` in the final card when `CM_PATH_LATER` is set.
- **Server** (`install_server`, 7 steps): needs Linux + systemd + root/sudo; domain (validated, DNS checked against the public IP) or SSH tunnel only (127.0.0.1, free port); packages incl. Caddy (official repo if the distro has none) and ufw; `optimux` system user; `/opt/optimux` root-owned; `/var/lib/optimux` 750; `/etc/optimux/optimux.env` (OPTIMUX_SERVER=1); unit from `deploy/optimux.service` (TCP ExecStart in tunnel mode); Caddyfile from `deploy/Caddyfile` (old one kept as `Caddyfile.before-optimux`); firewall only with the detected SSH port(s) (`ssh_ports`: ss, `sshd -T`, SSH_CONNECTION; unattended + unsure → left off); optional unattended-upgrades; waits for the socket and for HTTPS.
- **optimux command:** `cli_start|stop|restart|status|logs|open|update|password|token|github|uninstall` (`cli_github` offers a restart after saving a token, since a running server reads secrets.env at start) via `svc` (systemctl, systemctl --user, or `process_ctl` with pid file + `server_pids` fallback). The background server gets `</dev/null` and `3<&-` so it never holds the terminal.

## set -e pitfalls (tests enforce)
A function must not end in `[[ x ]] && y` (returns 1 → the installer stops); `x="$(a | b)"` needs `|| true` under pipefail.

## Tests
`tests/test_install_script.py` (syntax, shellcheck, last-line rule, pitfalls, manifest round trip and not executed, package names, SSH port guess, card alignment, secrets only on stdin; Feature 27: old manifests found, a local install moved to the new names, the rollback when the new environment fails, nothing moved before the new code is there, the user service renamed, server units per name, an old server's ExecStart). Full installs are driven by hand in a container before a release.
