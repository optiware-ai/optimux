# gitsync.py

Push and Update from GitHub, run by Optimux on the user's click (v0.4-5t). Never a model tool.

- **Two steps each:** `push_prepare(name)` / `update_prepare(name)` read and fetch, change nothing, and return what the dialog shows, with `problems` (blocking) and `warnings` (need "I checked"). `push_run(name, message, tree, confirmed)` / `update_run(name, sha)` prepare again and refuse when the pinned value moved: the working tree (`tree`, built like changes.py with a temp index) or the upstream commit (`sha`). One lock per project (`_lock`), non-blocking.
- **Branches:** `_basics` reads the remote (`_clean_remote`), the branch (`symbolic-ref`; detached is refused), fetches (`--no-tags`), and picks the target with `workspace.copy_target`: a copy pushes to and updates from its own branch. `_counts` gives ahead/behind against `refs/remotes/origin/<target>`.
- **Push:** files = `changes.compare` between `HEAD^{tree}` (or the empty tree) and the working tree. Problems: no origin, detached HEAD, no identity git can commit with (`workspace.git_can_commit`: the settings, or a `user.email` plus `git var` author and committer working), a saved key's exact value in a file to commit (`_secret_values` = `security.secret_values()`: secrets.env values ≥ 8 chars except `_API_BASE`, plus key-like server variables; only key names are shown), GitHub ahead (`behind`), nothing to push. Warnings: secret-like names (`SECRET_NAME`), files > 50 MB, fetch failed. Run: `git add -A`, `git commit --no-verify --cleanup=whitespace -F <tmp>` (so `#` lines stay), `git push -u origin HEAD:refs/heads/<target>`. Never `--force`. A refused push after a commit says the commit stays and Push sends it next time.
- **Update:** incoming commits (`log HEAD..upstream`, up to 30), incoming files (`diff --name-status HEAD upstream`), local changes (`diff --name-only HEAD` + untracked). Problems: no origin/branch upstream (a copy never pushed), fetch failed, up to date, diverged (ahead and behind), a local change to an incoming file. Run: `git merge --ff-only <sha>`.
- **Status (v0.8):** `status_report(name)` for the Project page's terminal window: `_basics(fetch=True)` (only remote branches move), `git --no-optional-locks status --branch` (never writes the index), `git log --oneline --decorate -n 5`, and `ahead`/`behind` against `origin/<target>` (None without an upstream). Refused while a push or update holds the project's lock. Each output is cut at 20,000 chars, URL credentials removed and saved keys masked (`security.mask_secrets`, edges). Returns `{project, remote, branch, target, copy_of, upstream, ahead, behind, steps: [{command, ok, output}]}`; `command` is the plain git command shown, not the real argv.
- **Identity (v0.8):** `identity_report(name)`: `git var GIT_AUTHOR_IDENT` (through `_env`, so Optimux's identity setting applies; the timestamp is cut), `git remote get-url origin` (url.insteadOf applies, as for git itself), then by remote kind: ssh (`ssh_target`: scp-like `[user@]host:path` or `ssh://[user@]host[:port]/path`; user and host must not start with "-", so a remote set by a model-run command can't become an ssh option) → `ssh -T -o BatchMode=yes -o ConnectTimeout=10 [-p port] -- dest` (never prompts, never adds a host key; `ok` when it exits 0 or the answer says authenticated, e.g. GitHub's exit 1 "Hi …!"); HTTPS GitHub with a saved token → `gh auth status --hostname github.com` (`github=True`); otherwise a note. Notes for `core.sshCommand` and an unknown host key. Steps go through `_shown` (cut, URL credentials removed, keys masked), shared with `status_report`. Returns `{project, remote, kind: ssh|https|local|none, steps, notes}`.
- **Git calls:** `_git` → `workspace._run` (hooks and fsmonitor off, no prompts, LLM keys scrubbed), `core.quotePath=false`; calls that talk to GitHub get `github=True` (GH_TOKEN in their environment only) and, for an HTTPS GitHub remote with a saved token, gh as the credential helper (`_auth`).
- **Commit message:** `message_material(name)` refuses when a file holds a saved key (a key never reaches a model), and returns the project's template (`_template`: `commit.template` if inside the project, `commit-template.txt`, `.gitmessage`, `.github/commit-template.txt`; cut at 4,000 chars), the last 5 subjects, the diff stat and the diff (cut at 15,000 chars). `message_prompt` asks to follow the template exactly (or subject ≤ 70 + body), lines ≤ 70, only what the diff shows. `clean_message` drops code fences. The call itself is in main.py (`POST /api/projects/{name}/commit-message`: Simple model, budget block respected, usage role `commit_message`).
- **Git pane (v0.8):** `local_state(name)` for the Studio's Git pane: `_basics(fetch=False)` (never touches the network: it refreshes after every reply), files vs `HEAD^{tree}` like `push_prepare`, ahead/behind against the last fetched `origin/<target>` (`ahead` 0 without one), identity, `_scan`; `can_commit` = files and no problems. A project without origin still works (commit only). `commit_run(name, message, tree, confirmed)`: same lock and checks as `push_run` (tree pinned, problems block, warnings need `confirmed`, message required), `git add -A` + commit, **no push**. Returns `{ok, project, commit, branch, files}`.
- **Git pane polling (v0.8):** `local_mark(name)`: a sha1 of HEAD, the remote branches (`for-each-ref refs/remotes`), `git status --porcelain=v1 -z --untracked-files=all` and the size and mtime of each listed file (first `MARK_FILES`), so an edit to a file already shown as changed counts. No fetch, no temporary index; '' without git.
- **Tests:** `tests/test_gitsync.py` (real repositories with a local bare repository as GitHub).

- **Remote check (v0.8):** `REMOTES_FILE` (`config/git_remotes.json`, mode 600) keeps where each project last pushed from Optimux (`remember_remote`, after a successful `push_run`). `push_prepare` puts a warning first when `origin` now differs (`changed_remote`): it names both addresses (masked) and must be confirmed like the other warnings. Tests isolate the file in `conftest.py`.
