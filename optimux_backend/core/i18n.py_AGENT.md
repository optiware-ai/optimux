# i18n.py Agent Details

## File Overview
`core/i18n.py` (v0.8) translates the texts the server writes for the page: error messages (`HTTPException` details and the errors core modules raise for them), the notes sent to the chat (`send(websocket, "system"|"error", …)`), Getting started, the security checklist, autonomy texts, snapshot and restore labels, provider labels, the Studio picker's labels. English is the source; the catalog is the page's own `web/i18n/<code>.json`.

## Core Functionality
- `tr(text, **values)`: the text in the language saved in Dashboard → System (`config_manager.language()`, read again only when the settings file changes), `{name}` placeholders filled from `values`. A text without a translation stays English.
- `tk(text)`: returns the text as it is. Marks texts in tables built at import (`autonomy.LEVEL_TEXT`/`REASONS`, `snapshots.DATA_ITEMS`, `restore.SENSITIVE`, provider labels in `catalog.PROVIDERS`, the legacy provider instructions); they are translated with `tr()` where used, at request time. Never call `tr()` at import: the language isn't known then and can change.
- Not translated, on purpose: everything sent to the models (prompts, tool descriptions, tool results such as `files.py`'s write/edit errors and the scout's tools), the phrases a user must type to confirm (`CONFIRM_PHRASE`, `DELETE_PHRASE`), and texts the page compares (`Execution finished (LLM loop gracefully aborted).`).

## Links & Dependencies
- Imported by most core modules and `main.py` (`from optimux_backend.core.i18n import tr`); it imports `config_manager` only inside `language()`, so there is no import cycle.
- Tests: `tests/test_i18n.py` collects every `tr("…")`/`tk("…")` with a written first argument from `optimux_backend/` (by parsing the code) and requires its translation; `test_the_server_speaks_the_language`.
