# changes.py

The changed-files summary under a reply (v0.4-5m): what the reply changed in the project's files, from git, with no model call.

- **`snapshot(workdir)`:** `{"git": False}` when `git rev-parse --show-toplevel` fails (no git), else `{"git": True, "top", "tree"}`: the project's files as a git tree, or `{"git": True, "error"}`. The tree is built by `_tree(top)`: `git add -A -- .` and `git write-tree` into a temporary index (`GIT_INDEX_FILE` in a temp dir, starting from a copy of the real `.git/index` so unchanged files aren't hashed again). The user's index is never touched; only objects land in `.git/objects` (like `git stash`). Files excluded by .gitignore are not seen. Every call drops outside `GIT_*` variables (`_clean_env`) and has a `TIMEOUT` (20 s).
- **`compare(before)`:** a second tree, then `git diff-tree -r --no-renames --name-status -z` and `--numstat -z` between them. Returns `{"git": False}`, `{"git": True, "error"}`, or `{"git": True, "files": [...], "more": n}` with at most `MAX_FILES` (30) files, warnings first. Each file: `path`, `status` (new | deleted | changed), `added`/`removed` (None for binary), `lines_before`/`lines_after` (counted with `git cat-file blob`, only for the first `MAX_COUNTED` (200) files), `warn`: deleted, or a changed file of at least `SHRINK_MIN_LINES` (20) lines that lost half its lines or more (the emptied index.html of the plan-mode measurement).
- **Used by** `main.mark_changes_start` (before the first approved command or file change of a request; nothing for chat-only replies, rejected commands, or without an active project) and `main.report_changes` (at the end of `_run_job`, also after a stop or an error; sends `changes` unless git worked and nothing changed).
- **Tests:** `tests/test_changes.py`.
- **Racily clean entries (fixed in 5t):** the temp index is copied with `shutil.copy2`, keeping the real index's mtime. With a fresh mtime, git trusted stale stat data and missed a file edited at the same size in the same second the index was written (e.g. right after a clone), when the snapshot ran a second later. `test_a_same_size_edit_right_after_a_clone_is_seen` reproduces it.
